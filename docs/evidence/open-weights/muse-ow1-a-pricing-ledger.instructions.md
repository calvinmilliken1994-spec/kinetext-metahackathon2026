The product will run the SAME pipeline either on Meta's hosted API (`muse-spark-1.3`, provider `meta-api`) or on the open-weight model Muse Spark Open hosted on a Modal Shared Endpoint (exact model string `meta-models/Muse-Spark-Open-816B-A42B`, provider `modal`). This call changes ONLY `pricing.ts` and `ledger.ts` (+ tests). The client (`client.ts`) is changed in the NEXT call and must keep compiling and passing its existing tests against your new pricing/ledger API (it calls `reservationUSD('muse-spark-1.3', …)`, `costFromUsage('muse-spark-1.3', usage)`, `ledger.reserve({ purpose, model, estUSD })`, `ledger.reconcile(…)`, `openLedger({ path, capUSD, lockPort? })`). ## Required changes

### pricing.ts
1. Export `type ModelChoice = 'muse-spark-1.3' | 'muse-spark-open'` (display id chosen per job) and `type MetaProvider = 'meta-api' | 'modal'`. Export `const MODEL_CHOICES: readonly ModelChoice[]` and `const META_PROVIDERS: readonly MetaProvider[]` (in that order), plus `function isModelChoice(v: unknown): v is ModelChoice` and `function isMetaProvider(v: unknown): v is MetaProvider`.
2. `PRICES_PER_MTOK: Record<ModelChoice, { input: number; cachedInput: number; output: number }>` with `'muse-spark-1.3'` unchanged and `'muse-spark-open': { input: 1.25, cachedInput: 0.15, output: 4.25 }` (Modal Shared Endpoint per-token price, same as Meta's).
3. `costFromUsage(model: ModelChoice, usage)` and `reservationUSD(model: ModelChoice, inputTokens, maxOutputTokens)` accept both. A runtime value that is not a ModelChoice (e.g. a cast string) throws `new Error('UNKNOWN_MODEL')` (checked with `Object.hasOwn`/`isModelChoice`, never by reading an inherited property). Existing behaviour and error messages for valid models are unchanged (`INVALID_USAGE`, `INVALID_AMOUNT`).
4. `isValidUsage` and `inputTokenBound` unchanged. Note: cached tokens that a provider does not report are passed in as `cachedTokens: 0` by the client, so `costFromUsage` charges the full input price (conservative); no change needed here beyond a doc comment.

### ledger.ts
1. `LedgerEntry` gains `provider: MetaProvider` (import the type from `./pricing.ts` with `import type`). Every newly written entry (reserve and reconcile) includes `provider`. A reconcile entry copies the provider of its reservation.
2. `Ledger.reserve(req: { purpose: 'test-live' | 'demo'; model: string; estUSD: number; provider?: MetaProvider })` — `provider` defaults to `'meta-api'` (existing callers unchanged). A present value that is not a MetaProvider throws `new Error('INVALID_PROVIDER')` before anything is written.
3. Replay (`replayLedgerFile`): a line WITHOUT a `provider` field is a legacy entry and counts as `'meta-api'` (existing `storage/ledger.jsonl` files must keep replaying unchanged). A present `provider` that is not a MetaProvider → `LEDGER_CORRUPT`. A reconcile entry whose (defaulted) provider differs from its reservation's provider → `LEDGER_CORRUPT`. All other existing replay rules unchanged.
4. `openLedger` opts gain `providerCapsUSD?: Readonly<Partial<Record<MetaProvider, number>>>`. Validate at open: each present value must be a finite number ≥ 0 (else `INVALID_AMOUNT`); any key that is not a MetaProvider → `INVALID_PROVIDER`. Validate BEFORE binding the lock port (so a bad config does not hold the port).
5. Cap semantics in `reserve` (after the existing re-read of the file):
   - `providerCapsUSD` absent (all existing callers): UNCHANGED — total committed across all providers + estUSD > capUSD → `BUDGET_EXCEEDED`.
   - `providerCapsUSD` present: let P be the reservation's provider. If `providerCapsUSD[P]` is undefined → `BUDGET_EXCEEDED` (fail closed: a provider without a configured cap cannot spend). If committed(P) + estUSD > providerCapsUSD[P] → `BUDGET_EXCEEDED`. If P is `'meta-api'`, ALSO committed('meta-api') + estUSD > capUSD → `BUDGET_EXCEEDED` (the existing stage cap remains for meta-api). Modal spend does NOT count against capUSD in this mode.
   - committed(P) uses the same rule as today (reconciled → actual, unreconciled → estimate), restricted to reservations of provider P (legacy entries are meta-api).
6. `Ledger.committedUSD(provider?: MetaProvider): number` — total across all providers when omitted (unchanged), per provider when given. `Ledger` gains `readonly providerCapsUSD: Readonly<Partial<Record<MetaProvider, number>>> | undefined` (a frozen copy of what was passed, or undefined).
7. Lock, port, close, append and error behaviour unchanged. Keep the lock-notes comment.

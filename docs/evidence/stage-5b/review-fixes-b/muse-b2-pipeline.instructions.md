## Required guard semantics (`repair.analysis-unchanged`, in pipeline.ts; replace `allowedAnalysisGroups`/`checkAnalysisUnchanged`)

G2. If the baseline is not a plain object with array `concepts` (each a plain object with array `evidence`) and array `objectives`, the guard fails (cannot compare safely).
G3. Expected-value construction (suggested implementation; any equivalent is fine): build `expected = structuredClone(baseline)`, then apply the unlocks below from the candidate, then the guard passes iff `isDeepStrictEqual(expected, candidate)`. Report every differing JSON pointer (compute a structural diff) — the failing message lists them (truncated for display), `path` = the first differing pointer (e.g. `/objectives/0`, `/concepts/0/name`, `/concepts`, `/supported`), and the failing guard check carries NO `affected` (it is not a field-scoped validator finding and must never authorize anything).
G4. Unlock rules (each from A only):
  - Decision: if `/supported` ∈ A or `/activity` ∈ A, both `supported` and `activity` (one decision) and `unsupportedReason` come from the candidate. Otherwise all three stay frozen, except `unsupportedReason` alone when `/unsupportedReason` ∈ A.
  - Objectives: `/objectives/<i>` ∈ A unlocks exactly that string. List length stays the baseline length; only if `/objectives` ∈ A may the candidate APPEND entries after the baseline entries (baseline entries keep their positions and stay frozen except their own unlocked indices). No deletion, no reordering ever.
  - Concepts: matched by POSITION (identity is position + content, never the possibly-changed id). Length stays the baseline length; only if `/concepts` ∈ A may the candidate APPEND new concepts after the baseline concepts (never delete). For baseline concept i: `/concepts/<i>/id` unlocks only its `id`; `/concepts/<i>/name` only its `name`; `/concepts/<i>/evidence/<j>/quote` only that quote; `/concepts/<i>/evidence/<j>/sourceId` only that sourceId; `/concepts/<i>/evidence` lets the candidate APPEND evidence entries to concept i (existing entries frozen except their own unlocked fields; no deletion). Nothing else of concept i may change (no other keys added/removed).
  - Any other top-level key change (added, removed, changed) is rejected. A path in A that does not resolve in the baseline but resolves in the candidate (e.g. a schema-reported missing property) unlocks setting that property; a path that resolves in neither changes nothing.
  - Unknown/unlisted paths unlock nothing. A failing baseline check with no `affected` unlocks nothing (fail closed).
G5. Passing message: `no field changed` or `changed only authorized fields: <pointer list>` plus `(authorized by baseline findings <check ids>)` — display only. Keep id `repair.analysis-unchanged`, kind `semantic`.
G6. `repairAnalysis` passes the authorized set to the prompt: `buildAnalysisRepairMessages(source, previous.analysis, findings, <original or undefined>, authorizedPaths)` where `authorizedPaths` = A as computed in G1 (array, report order, deduplicated), `original` = `baselineAnalysis` only when `previous.baseline` is given (as today).

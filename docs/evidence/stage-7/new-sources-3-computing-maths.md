## Page styles our components may not serve yet

For the subject-engine design (computing especially):

1. **Code/pseudocode lines.** DADS binary search prints two code lines (`mid = (high + low)/2;`, `mid = low + (high - low)/2;`). The kit renders prose only — no monospace/code component, and the formula explorer's small maths language does not model assignment statements or semicolon-terminated code.
2. **Formal definitions with inequalities and quantifiers.** Big-O's formal definition ("there are positive constants c and k, such that 0 ≤ f(n) ≤ cg(n) for all n ≥ k") is checkable by sampling (the page's own worked example uses n > 10, c = 2), but no current engine parses a universally-quantified inequality; the formula explorer only verifies equations.
3. **Algorithm traces / per-pass state.** Sorting and searching are naturally taught as step-by-step traces over an array (each pass of bubble sort, each halving of binary search). The sequence component orders steps but cannot show intermediate array/interval state; a "trace player" (deterministic, data-only) would be the highest-value new computing component.
4. **Chained computation tables.** BLS rebasing's table computes each row from the previous row's output (`100.434 * 1.00595 = 101.032`), and cells embed arithmetic with trailing '=' signs. A formula explorer covers one formula, not an iterated table; quiz/quote checks must treat cell arithmetic strings as page text tokens.
5. **Branching decision flows.** FTC's "Do I have an account with the company…? No → report and delete; Yes → contact via a known-real number" is a two-branch decision tree. Sequence is linear; there is no branch/decision component (a scenario card with two paths would serve phishing, incident response, etc.).
6. **Explicit taxonomy edges.** DADS entries ship machine-readable relationships (Generalization / Specialization / Aggregate parent / Aggregate child / See also). The concept map is Muse free-form today; these labelled edges could bind a concept map deterministically — an opportunity, not a gap.
7. **Data-widget tables whose values are not in the page text.** Census's 48 poverty thresholds live in a linked widget; only the card text ("Table Poverty Thresholds … Source: Current Population Survey (CPS)") is on the page. Coverage/quote checkers must not expect threshold values, and Muse must be steered away from quizzing numbers that are not in the stored text.
8. **Mixed Unicode maths notation.** Θ(n²), O(n^2) (caret-rendered superscript), n², ≤, §, ft^3/s versus ft³ appear across these pages in publisher-specific styles. The Stage-6 whole-token number normalisation needs an exponent-aware equivalence (n² = n^2) before quiz/formula checks quote these reliably.
9. **Served-text quirks.** USGS duplicates a glossary paragraph; Census prints "$39,384= 1.01" without a space; a DADS contributor email arrives Cloudflare-obfuscated as "[email protected]"; BLS prints a literal footnote '1' inside a header cell. All kept exactly as served — validators must not "repair" them and quote matching must survive them.
10. **Statutory clause structure.** NASA's SI page embeds 15 U.S.C. § 9401(3) with (A)/(B)/(C) sub-clauses — enumerable structure a clause-matching quiz could exploit; nothing does today.

Served well by existing kit (for balance): glossary term/definition pairs (vocabulary), category comparison lists (compare table), numbered how-to steps (sequence), worked numeric examples with explicit bindings (formula explorer, quiz predict-then-reveal).

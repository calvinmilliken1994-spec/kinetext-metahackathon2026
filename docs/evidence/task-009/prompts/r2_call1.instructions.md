### Interface decisions from the lead (follow exactly)
- Remove `createLedger`, the PID lock file (`<path>.lock`), `acquireLock`, `releaseLockIfOwned`, the module-level held-lock set, the `process.on('exit')` listener and all stale-lock takeover code. No `.lock` file may be created any more.
- New export `defaultLockPort(ledgerPath: string): number` = `49152 + (u32 % 16000)`, where `u32` is the first 4 bytes, read as an unsigned big-endian 32-bit integer, of `createHash('sha256').update(path.resolve(ledgerPath), 'utf8').digest()`. Range is therefore 49152..65151.
- New export `async function openLedger(opts: { path: string; capUSD: number; now?: () => Date; newId?: () => string; lockPort?: number }): Promise<Ledger>`. Steps in order:
  1. Validate `capUSD` (finite, >= 0, else reject with `Error('INVALID_AMOUNT')`). If `lockPort` is given it must be an integer 1..65535, else reject with `Error('INVALID_LOCK_PORT')`. Nothing is listened on when validation fails.
  2. Create the ledger's parent directory if needed (`mkdirSync(dirname(path), { recursive: true })`).
  3. Acquire the lock: `net.createServer()` and `listen({ host: '127.0.0.1', port: lockPort ?? defaultLockPort(path), exclusive: true })`, awaiting `'listening'` or `'error'` (remove the other listener afterwards). Do not set any address/port-reuse option. `EADDRINUSE` → reject with `Error('LEDGER_LOCKED')`. Any other listen error (e.g. `EACCES` for a port the OS has excluded) → reject with `Error('LEDGER_LOCK_FAILED')`: fail closed, never continue without the lock. The listening server IS the lock; the OS releases it automatically when the process dies, so stale locks cannot exist. Call `server.unref()` so the lock never keeps the process alive, and destroy every incoming connection immediately (`server.on('connection', (s) => s.destroy())`). Keep a no-op `'error'` listener on the server after it is listening so a late socket error cannot crash the process.
  4. Replay the ledger file (unchanged validation, `LEDGER_CORRUPT` on any malformed line etc.). If replay throws, close the server (release the lock) before rethrowing.
- `close()`: synchronous, idempotent, closes the lock server; afterwards `reserve`/`reconcile` throw `Error('LEDGER_CLOSED')`. In the same process, `ledger.close(); await openLedger({ path: samePath, ... })` must succeed straight away (test it).
- Keep, unchanged in meaning: re-read + replay of the file immediately before each `reserve` cap check (defence in depth), `BUDGET_EXCEEDED` writing nothing, `INVALID_AMOUNT` for non-finite/negative `estUSD`/`costUSD`, `UNKNOWN_RESERVATION`, all replay validation, `committedUSD()` semantics.
- Write an honest code comment above `openLedger` stating what the lock guarantees (one owner per ledger path among processes on this host that use `openLedger` with the same port derivation; released by the OS on process exit or crash) and what it does not (a foreign program already bound to that port makes `openLedger` fail closed with LEDGER_LOCKED/LEDGER_LOCK_FAILED; two different path spellings of one file — e.g. letter case on Windows, symlinks — derive different ports and are not mutually excluded; writers that do not use `openLedger` are not excluded, which is why the re-read before reserve stays).

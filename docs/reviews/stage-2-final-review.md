### Why F-01 is not the old N-03 probe

N-03 concerns the outer HTTP response: `null` or `choices:[null]`. Those now fail safely inside `complete()` with reservation-bearing MetaError metadata. F-01 uses a structurally valid response envelope whose **content string parses to schema-invalid JSON**. The transport has already correctly reconciled and supplied its receipt. Downstream code discards that receipt or dereferences invalid data outside the normal failure finalizer. Constrained decoding is not a substitute for safe handling when local schema validation has explicitly failed.

The ledger remains conservative in every reproduced F-01 case; the defects are false job totals and stale persisted lifecycle state. The null-analysis bug exists in the prior worker ordering, and the spec-assembly dereferences predate round 2. Round 2's live-owner protection is correct but now ensures these stale jobs are not repaired while the owning API remains alive. This report does not misattribute those original dereferences to the new client implementation.

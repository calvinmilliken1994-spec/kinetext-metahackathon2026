## Specific assessment of Muse-authored `packages/meta`

**Independent approval is withheld pending fixes.** The code is readable, compact, and has useful fake-transport tests, but its most important guarantees are only tested on cooperative responses.

### What is implemented correctly

- `client.ts:111-117` requires explicit live opt-in and a key before constructing a usable live client. `complete()` reserves before sending; a denied reservation sends no request.
- Requests use the exact `muse-spark-1.3` default, High reasoning, non-streaming chat completions, and `response_format: json_schema` (`client.ts:151-160`). No alternate provider/model fallback was found.
- Retries are bounded to two attempts and only the explicitly listed transient statuses; auth/input/network/timeout failures are not blindly retried. The problem is accounting and total deadlines, not an unbounded loop.
- Exact returned-model matching, stop-reason checking, nonempty content, and JSON parsing are checked. Model-output errors with reported usage retain receipts. Completely absent usage falls back to the reservation.
- Pricing correctly separates cached input from uncached input for coherent usage and does not double-add reasoning tokens already included in completions. Rates match the approved task specification; current provider pricing was not independently fetched during this review.
- An unreconciled, valid persisted reservation is counted on normal replay; unknown/double reconciliation is rejected by one ledger instance. Append-before-in-memory-update avoids sending after a failed reservation append. This is not proof of power-loss durability: no fsync/transactional storage is used.
- Prompts explicitly describe sources as untrusted, require exact quotes/source IDs, and forbid publisher attribution. These are useful instructions but do not establish scientific entailment or eliminate injection.
- `pipeline.ts` passes generated output through deterministic validation and assembles IDs, sources, engine/equation, provenance, and execution policy using system code. Top-level model-supplied execution/provenance cannot overwrite those fields. Validation failures are returned for the worker to block rather than silently repaired by another model.

### Why passing TASK-004 tests is insufficient

Some defects originate in the task contract itself: it specifies `chars/3` as conservative, a single reservation before a retry loop, and allows a truncated provider error message. Following those instructions does not satisfy the stronger resource/privacy policy. Revisit the contract as well as the implementation.

- `client.test.ts:528-565` does not include a secret-bearing error body; it establishes only that cooperative response strings do not leak a key.
- Missing usage is tested (`client.test.ts:464-484`), but empty/partial/incoherent usage is not.
- The retry tests check attempt counts and even codify one reservation for two uncertain attempts; they do not verify per-attempt conservative liability.
- Ledger replay tests use sequential instances (`ledger.test.ts:77-125`), not two writers whose snapshots overlap. Synchronous code avoids a race only when everyone shares the same instance.
- Prompt tests check presence of instructions and tags, not delimiter breakout or behavior under injected instructions.

Required regression additions should cover R-01 through R-06 and R-09, plus invalid ledger/config numbers, corrupt/truncated ledger records, body-read timeouts, and budget rejection between attempts/stages. Malformed ledger JSON currently fails startup rather than resetting to zero, which is safer than silently dropping commitments, but recovery needs an explicit procedure.

## Other behavior verified as correct

### Physics, contracts, references

- The engine uses `a=F/m`, `v=v0+a*t`, and `x=x0+v0*t+0.5*a*t*t`; it samples from indexed times rather than cumulative integration. Tests exercise positive/negative/zero force, nonzero initial state, the final sample, and allocation caps. No physics defect was found for schema-admissible UI inputs.
- The full schema allowlists the engine and equation, forbids arbitrary properties/executable fields, bounds simulation parameters and numerical expectations, and fixes `network`/`generatedCodeAllowed` to false. Frame-count validation uses the real simulator. No generated code execution path was found.
- Structured numerical behavioral tests and predictions are compared against the shared engine using the documented absolute tolerance; schema tolerance is capped at 0.01. The prompt's preferred 0.001 is not the schema-wide contract maximum. Predictions are checked against slider ranges.
- Spec-source references must resolve. The validator checks both stored hashes and recomputed text hashes, and source loading independently rejects changed text. Quote matching follows the documented case-sensitive whitespace normalization except for the empty-evidence hole in R-05.
- Source/job IDs from HTTP are constrained before filesystem access; encoded slash/backslash/dot traversal cannot reach arbitrary files through the reviewed ID routes. Metadata `textFile` and injected test job IDs remain trusted local inputs, not HTTP-uploaded values. No remote source/model URL is fetched from model-generated content.

### Worker/API

- Supported, unsupported, validation-failure and Meta-error paths are genuinely exercised. Unsupported analysis ends without a spec. Failed validation is not upgraded to success or repaired invisibly. Events have real persisted stage transitions and monotonic sequence values in the normal path.
- `main.ts:33-39` really reads `stageCapsUSD.stage2` and wires it into the ledger, defaulting an absent stage cap to zero. The checked-in cap is $10. This is real configuration wiring, **not** a sufficient hard-cap guarantee given R-02/R-03/R-04/R-06 and unvalidated config values.
- Production entry-point binding is `127.0.0.1`; Vite development binding is also loopback. The API does not emit permissive CORS headers. These reduce exposure but do not replace R-07's authorization controls.
- HTTP tests verify 202 acceptance, 409 while an in-process job runs, 503 when live generation is disabled, 400 malformed bodies, 413 oversized bodies, 415 wrong media type, and 404/405 routes. The 10 KiB body limit covers declared size and streamed chunks. Responses set JSON content type, `nosniff`, and `no-store`.

### React UI and trust boundaries

- React renders source/model text as text nodes/attributes, not HTML; SVG geometry uses tested engine output, not generated markup/code. Source locator links come from trusted source metadata, not model output.
- `useSimulation.ts:5,47-61` imports `simulate`, `stateAt`, and `accelerationOf` from the same engine the validator uses. Prediction grading likewise calls that engine instead of trusting the model's stored expected answer.
- Prediction cards reveal the engine's result only after a submitted guess (`PredictionCards.tsx:22-39,67-74`). The expected-value field is still in the HTTP spec, so this is pedagogical UI hiding, **not** answer confidentiality against developer tools. Arbitrary model-written question prose is subject to R-08.
- Run badges say “Live run” only for IDs created by this browser session; stored runs are labeled “Recorded run” with a timestamp. Timeline rows come from actual events, with pending stages only while running; no fake repair stage is shown.
- Activity previews are gated on a succeeded worker summary. Publishing is disabled and explicitly deferred to teacher approval. Fixed AI-generation/no-NASA-endorsement disclosures are present, although they do not neutralize contradictory generated statements in R-12.

### Subscription bridge / smoke scripts

- `subscription_env()` strips the four documented API override variables (`META_API_KEY`, `MODEL_API_KEY`, `META_MODEL_API_KEY`, `META_BASE_URL`); local helper tests confirm this. The bridge uses the Muse subscription route and checks OAuth/subscription metadata and allowance before its execution command. It does not copy OAuth tokens into receipts.
- The bridge command fixes High reasoning, one model step, disabled shell/write/web/request-user-input, no foreign personal context, and no session log; a temporary workspace separates it from repository context. It requires configured and actual usage models to match, so a merely selected model name is insufficient for success.
- The standalone smoke fails closed for absent/malformed key or inadequate per-command approval and uses sanitized fixed error reasons. Its lack of a cumulative ledger is explicitly documented as a setup-only limitation; it must not become an unattended product entry point. It was not run live here.

## Test quality and coverage limits

The 177 tests are substantive rather than empty smoke assertions: they exercise real deterministic physics, source hashing, schema/semantic validation, a real worker behind ephemeral HTTP, and re-validation of committed run artifacts. The three Python tests are also honest pure-helper tests.

However, `tests/e2e/api-pipeline.test.ts:65-79` bypasses the real HTTP Meta client with recorded `MetaClient` output. That is legitimate pipeline integration coverage, not transport/spend integration or a browser E2E test. `tests/e2e/evidence-integrity.test.ts` proves consistency of the supplied artifacts and re-runs current checks; it cannot independently authenticate a historical provider transaction or prove prose correctness. Existing tests also lack React component/hook execution, process-interruption recovery, foreign-host requests, adversarial evidence, partial usage, reflected provider secrets, and overlapping ledger writers. The probes reproduced those gaps without changing the suite.

## Recommended fix order

1. Fix error confidentiality and add the reflected-marker end-to-end regression (R-01).
2. Make spend ownership atomic, account for every uncertain retry, validate all usage/money, and make reservations genuinely conservative (R-02/R-03/R-04/R-06).
3. Close evidence bypasses and correct the scope of “verified” claims (R-05/R-08); preserve human approval.
4. Add local API request authorization, failure-cost honesty, interruption recovery, and total resource budgets (R-07/R-09/R-10/R-11).
5. Tighten all-field source-use policy enforcement and delimiter handling before broader ingestion (R-12/R-13).

Re-run the deterministic suite, build, new adversarial regressions, and browser interaction checks before approving the next live demo.

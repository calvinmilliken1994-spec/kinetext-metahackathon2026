## Deployment-readiness notes

These are deployment requirements/decisions, not implementation changes made in this review.

1. **Judge authorization must be server-side.** `apps/api/server.ts:257-276,601-704` checks Host and optional Origin, not an access code. A client without Origin is allowed. Neither a hidden Generate button nor an Origin allowlist protects credits. Gate every spending submission and teacher-source write, while retaining GET-only public lessons. Do not expose an ungated alternate activity-flow or demo-fault spend path.
2. **Configure the actual public binding and HTTPS proxy boundary.** `apps/api/main.ts:158-181,193-199` binds 127.0.0.1 and does not supply a public allowedHosts list. `originAllowed` currently accepts only `http://` origins. A public host/reverse-proxy setup needs explicit trusted hosts, HTTPS-origin handling and no blind trust of forwarded headers.
3. **A judging-period $25 cap is not the current configuration.** The checked-in provider caps are Meta **$100** and Modal **$80**, with six concurrent jobs. Use an explicit judging-window budget shared across every enabled provider, retry and SAM call; two separate $25 provider caps would not be a $25 combined cap. Keep existing historical usage separate without deleting/reinitializing the authoritative ledger. No live balance was read here.
4. **Persist jobs and the ledger together; run one writer instance unless accounting is centralized.** The lock is a loopback port and admission is process-local. Separate hosts/ephemeral disks each have independent capacity. A redeploy or restart must not reset the judging allowance or lose accepted jobs. Include licensed stored demo lessons in the deployment, with truthful replay labels.
5. **Add a usable kill switch and low public concurrency.** META_LIVE is read at startup, not a hot read-only/live switch. A guarded operational stop should reject new paid jobs without disrupting public stored lessons. Apply rate limits and bounded request/poll timeouts; repeated synchronous GET scans should not starve the generation process.
6. **Decide whether public paste is allowed.** GET source/job routes expose stored teacher sources and generated lesson artifacts without user separation. For the public demo, a library-only judge flow is the simpler privacy boundary. Any paste path needs the existing rights/product-improvement warning and an explicit public-retention policy. No private/student content should enter the free-credit runtime.
7. **Keep the figure corpus trusted and bounded.** Validate sidecar paths before file reads, not only before HTTP image serving. The worker currently sends/segments the first listed figure but accepts any id in its source figure list (`lesson.ts:1302-1323`). The current checked-in inventory has one figure per source; before adding multiple figures, enforce that the generated figureId equals the exact image segmented, or reload/resegment the selected image. Do not rely on the prompt's “use exactly this figureId” sentence as the gate.
8. **Narrow the public trust claim until the findings are closed.** Source-token presence and a segment around a point are useful checks, not proof of every entity/value or visual-label mapping. Keep teacher review explicit. Fix or explicitly triage the high findings before treating the current backend as ready for unsupervised public generation.
